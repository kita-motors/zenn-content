AI に仕事を任せるようになってから、自分が手を動かす時間が減って、その分「考える」とか「書く」時間が増えました。

ここ数ヶ月、Claude Code を業務に組み込んだことで仕事のスタイルがずいぶん変わってきたので、実際にやっていることや、試行錯誤の中で出てきた小さなチップスをここに書いていこうと思います。

## 何をやっている人間か

中小企業の事務・管理部門に所属する非エンジニアです。プログラミングは目的ではなく、現場の困りごとを減らすための手段として書いています。

ただ、基礎については以前エンジニアの方に教わっていた時期があり、その下地の上で今は独学＋AI と二人三脚で書いている、というのが正直なところです。

それでも気づけば、社内向けに以下のようなものを内製してきました。

- 定期連絡やリマインドを自動化する社内チャット Bot
- クラウド勤怠 SaaS の打刻データを自動確認して通知・申請を出す Web アプリ
- クラウド請求書 SaaS と社内システムを繋ぐ半自動化ツール（ブラウザ拡張、複数）
- 基幹システムをブラウザ拡張で一括操作するツール
- 経理の突合せ業務を自動化するシステム
- 生成 AI と連携した社内向け Q&A チャットボット
- グループウェア同士のスケジュールを同期する GAS

ほか、細かいものを含めていくつか。

本業の外でも、Claude Code の会話を長期記憶化する CLI（Supabase + pgvector + 生成 AI）を書いたり、Android アプリをいくつか作ったりしています。

どれも一人で AI と壁打ちしながら作ったもので、非エンジニアでもここまでは作れるんだな、というのが正直な感想です。「現場の摩擦を技術で削る」という目的に対して、AI が加わったことで削れる範囲が一気に広がってきた、という感覚があります。

## このアカウントで書くこと

二本柱で書いていく予定です。

### 1. Claude Code / AI エージェント運用の実践知

「Claude Code とは何か」のような入門記事は本家のドキュメントが一番詳しいので、私が書くのはそこに書かれていない実務の話になります。

- Claude Code をプロジェクトに組み込んだら何が変わったか / 何が変わらなかったか
- サブエージェントや MCP サーバーの設計と、どこで AI に任せてどこで人間が判断するか
- 失敗例: AI に任せて事故った話、コンテキスト窓の使い方を読み違えた話
- 非エンジニアならではの詰まり方と、そこからの抜け出し方

### 2. 業務自動化の現場ハマりどころ

GAS や API 連携で業務フローを自動化していると、ドキュメントに書かれていない仕様差で1日溶ける、というのが頻繁に起きます。そういうのを残していきます。

- グループウェアやクラウド SaaS の API 仕様の罠
- 中小企業 DX の現実: 「動いて当たり前」を作るためのコスト
- ブラウザ拡張機能で基幹システムを操作するときの設計
- データ同期で起きた事故と回避策

## 第1弾予告

そもそも私が Zenn を始めようと思ったきっかけは、これから書く記事の話を残しておきたかったから、というのが正直なところです。

**「Claude Code に長期記憶を持たせる MCP サーバーを作った話（kita-memory）」**

セッションが変わるたびに過去のやりとりを忘れていく Claude Code に、自分の壁打ち履歴や業務メモを引かせたくて、Supabase + pgvector で会話を貯める CLI と、それを Claude Code が叩けるようにする MCP サーバーを書きました。設計の試行錯誤、なぜそれが業務に効くのか、非エンジニアが MCP サーバーを実装するときに引っかかったポイント、あたりを書く予定です。
